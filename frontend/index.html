core features

🔐

Auth System

JWT access + refresh tokens, bcrypt password hashing, token blacklist on logout, secure cookie handling.

🛡️

Role-Based Access

Two roles: user and admin. Middleware guards protect routes. Admins can manage all tasks + users.

📋

Tasks CRUD

Full create/read/update/delete on tasks entity with filtering, pagination, and status management.

🔬

Validation + Docs

Zod schema validation, Swagger/OpenAPI docs at /api/docs, structured error responses with codes.

scalability architecture note

⚡

Horizontal Scaling

  • Stateless JWT → any instance handles any request
  • Load balancer (Nginx / AWS ALB)
  • PM2 cluster mode for multi-core
  • Docker + Kubernetes for auto-scale
💾

Caching (Redis)

  • Cache user sessions and profiles
  • Rate-limit counters per IP/user
  • Refresh token blacklist TTL
  • Task list cache (invalidate on write)
🗄️

Database

  • Connection pooling (PgBouncer)
  • Read replicas for GET endpoints
  • Indexed on email, user_id, status
  • Migrations via Prisma
🧩

Microservice Path

  • Auth service → separate container
  • Task service → own DB + port
  • API Gateway for routing/auth
  • Message queue (Bull/RabbitMQ)
🔍

Observability

  • Winston structured logging
  • Request ID tracing (UUID per req)
  • Prometheus metrics endpoint
  • Health check at /api/health
🛡️

Security Hardening

  • Helmet.js for HTTP headers
  • express-rate-limit per IP
  • Input sanitized via Zod
  • CORS whitelist config
Current: monolith → next step: extract auth into a dedicated microservice using JWT RS256 so the task service can verify tokens independently. Add message broker for async notifications, CDN for static assets, and PostgreSQL → Citus for distributed queries.
